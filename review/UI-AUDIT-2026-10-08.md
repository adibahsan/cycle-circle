# UI audit: web + admin (2026-10-08)

`/impeccable audit` run against `feat/cycle-circle-rebrand` @ `5b709c8` (PR #29, v2.0.0 rebrand). The audit covers every web page in light and dark, on desktop (1366×900) and phone (390×844 and 375×667), with every reachable pop-up opened. It also includes a code-level audit of web and admin across accessibility, performance, theming, responsive layout and implementation integrity.

Prompted by: *"the UI is looking sloppy, missing many alignments, looking bad in dark mode & having issues with the pop-ups."* Each part of that complaint traces to a root cause below.

### Implementation integrity verdict: **Fail (systemic, fixable)**

The brand layer is coherent: tokens, the on-* text pairs and the logo usage all hold up. The structure under it doesn't.
- No shared page shell: the header, container, vertical rhythm and title size differ per page.
- No shared overlay shell: each of 10 overlays reimplements backdrop, ESC, scroll lock and phone geometry, with different results.
- The phone app chrome doesn't fit a phone.

These three causes produce most of what the user describes as "sloppy". They should be fixed once, as shared primitives, rather than patched page by page.

### Executive summary
- **Issues:** P0 1 · P1 30 · P2 ~55 · P3 ~11, across web and admin. The P1 count includes 7 admin P1s; the detailed reports hold the full list.
- **Top 5:**
  1. The phone shell overflows on every signed-in page, and the header and bottom nav are clipped. → `adapt` / layout shell
  2. Overlays have no shared contract: dead ESC on 5, no focus trap anywhere, colliding stacks, clipped sheets on short phones, and a P0 where the trial modal is trapped inside the blurred sidebar. → one modal shell
  3. Dark mode: the theme applies after hydration (white flash), focus rings get a white halo, surfaces and borders don't separate, and two tints are broken. → theming tokens + pre-paint script
  4. Alignment: page title, container, section gap and card width rules differ on every page, and half-width cards sit next to full-width siblings. → page shell + spacing scale
  5. Correctness bugs that show up visually: `/profiles` fails hydration because buttons are nested, and the calendar's "This Cycle" fertile range is wrong.
- **Next step:** settle the cross-cutting decisions (modal shell, page shell and spacing scale, dark surface tokens) with `/grill-with-docs`, then `/to-spec` → `/to-tickets` grouped as in "Fix groups" below.

## Verified findings by severity

### P0

**[P0] Trial "add number" dialog is trapped inside the blurred sidebar or header** ✔
- **Location:** `components/TrialCountdownPill.tsx:315` renders `<Modal>` without a portal (`components/ui/Modal.tsx` has no `createPortal`). It's mounted inside `.glass` containers at `app/(main)/layout.tsx:412` (sidebar) and `:529` (mobile header). `.glass` uses `backdrop-filter` (`globals.css:148-151`).
- **Impact:** `backdrop-filter` creates a containing block, so the "fixed" backdrop and dialog are laid out inside the 256px sidebar on desktop, or inside the sticky header on phones. Email-trial users can't reach the add-number flow, which is the upgrade path.
- **Fix:** render every overlay through a portal to `document.body` in the shared shell.

### P1: responsive and app shell

**[P1] Horizontal scroll on every signed-in page on phones** ✔ measured
- **Location:**
  - `app/(main)/layout.tsx:529-562`: the mobile header's right cluster (`Rina` chip, `Profile` ring chip, theme, `EN / BN`) ends at x=403.
  - `:581-611`: the bottom nav has 6 links with `px-3` each and ends at x=417.
- **Evidence:** `document.documentElement.scrollWidth` is 404 at both 390 and 375 viewports on dashboard, calendar, symptoms, insights, content, profiles, settings, subscription and feedback. Screenshots: `screen-*-phone*.png`, `page-dashboard-light-phone.png`.
- **Impact:** the whole app pans sideways and the EN/BN toggle is cut off ("EN / B"). The "Cycle Circle" wordmark wraps to two lines, and the bottom-nav labels for the last items are clipped. Bengali labels make it worse.
- **Fix:**
  - Header: drop the duplicate profile chips on phones and keep the wordmark to a single line. Move the theme and language toggles into Settings or an overflow menu.
  - Bottom nav: limit it to 5 items, or use icon-first `flex-1` items. Add `env(safe-area-inset-bottom)`.

**[P1] Symptoms save bar overlaps the bottom nav** ✔
- **Location:** `symptoms/SymptomsClient.tsx:596` (`fixed bottom-[60px]`). The nav is about 67px tall, and no `safe-area`/`env(` is used anywhere in `apps/web/src`.
- **Screenshot:** `screen-symptoms-*-light-phone.png`.
- **Fix:** expose a `--bottom-nav-h` CSS variable from the shell. Offset with `calc(var(--bottom-nav-h) + env(safe-area-inset-bottom))`.

**[P1] Two-column layouts break against the 256px sidebar.** The `md:`/`lg:` breakpoints are measured against the viewport rather than the content column, so columns end up 200–300px wide. Details are in `layout.md`.

**[P1] Page title treatment differs on every page** ✔ (screenshots)
- Dashboard has no h1, Calendar and Symptoms use `text-xl`, Insights uses `text-2xl extrabold` with an icon, Content uses an `h2`, and Settings, Subscription and Feedback use `text-2xl md:text-3xl`. The full table is in `layout.md`.
- Combined with per-page `py-3`/`py-4`, `gap-4`/`gap-5`/`space-y-6`, this is the main source of "missing alignments" when you move between pages.

### P1: overlays (see `modals.md` for the full comparison table)

- **[P1] Only `Modal` has a shared contract.** The other 9 overlays are hand-rolled, and ESC does nothing on 5 of them: the Subscription dialogs, the Profiles edit and delete dialogs, the Settings logout confirm and `PeriodLogModal`.
- **[P1] No overlay traps focus or uses `inert`, and none restores focus on close,** except `OnboardingTour` (`ui/Modal.tsx:48-80`).
- **[P1] Overlays collide when stacked** ✔ (screenshot `pop-trial-expired-light-phone.png`).
  - Everything sits at `z-50` except the tour and late alert (`z-60`) and the lock (`z-80`), so stacking follows DOM order.
  - On the dashboard, the check-in sheet auto-opens beneath the trial lock. The auto check-in also beats the trial-pill modal.
  - Check-in → QuickSymptom → Celebration nest inside each other (`TodayCheckInModal.tsx:331-364`).
- **[P1] Body scroll lock is unreliable.** Four overlays write `body.style.overflow` unconditionally and clobber each other. Seven overlays have no lock at all.
- **[P1] `ProfileCompletionModal` and the Profiles edit dialog have no max-height or internal scroll.** At 667px the form is clipped. The edit dialog only just fits at 844px (`pop-profile-edit-light-phone.png`).
- **[P1] On phones the onboarding tour card covers the bottom-nav items it spotlights** (`OnboardingTour.tsx:307-313`).
- **[P1] `TrialExpiredLock` nests interactive elements and doesn't contain the app underneath** (`TrialExpiredLock.tsx:88-96`).

Also visible in the screenshots:
- The check-in sheet at 375×667 runs flush to the bottom edge with no safe-area padding, and it's cut on the right because of the page overflow (`pop-checkin-light-phone-se.png`).
- Phone geometry differs per overlay: floating `mx-4` sheet, flush sheet, centred card.
- Backdrop blur and opacity differ per overlay.

### P1: dark mode / theming (see `theming.md`)

- **[P1] The theme is applied in a post-hydration `useEffect`, so dark users get a white flash** ✔ (`components/Providers.tsx:10-13`). Admin has the same bug (`apps/admin/src/components/Providers.tsx:9-12`). Fix it with a blocking inline script in `<head>` that sets `.dark` and `color-scheme` before first paint.
- **[P1] `ring-offset-2` without an offset colour paints a white halo around focus rings in dark** ✔. There are 60 uses in web and 47 in admin. Only `CelebrationModal` and `TodayCheckInModal` set `--tw-ring-offset-color`. Fix it once with a global `--tw-ring-offset-color: var(--color-bg-card)` on `:root`/`.dark`.
- **[P1] Dark surfaces and borders are too close.** Cards, inputs and nested panels barely separate (`globals.css:85-93`, `:118-123`). It's visible in every `pairs/*-desktop.png` dark half.
- **[P1] Form-control borders and the switch "off" state fail the 3:1 non-text contrast minimum, worst in dark** (`ui/Input.tsx:26`, `SettingsClient.tsx:129-137`).
- **[P1] Two tints are built as a CSS variable plus a hex alpha suffix, which is invalid CSS** ✔ (`` `${color}20` `` when `color` is `var(--…)`): `DashboardClient.tsx:853` and `ContentClient.tsx:337`. The browser drops the declaration, so the tint never renders. Use `color-mix(in srgb, var(--x) 12%, transparent)` per contracts.md.

### P1: correctness bugs that show up in the UI

- **[P1] `/profiles` fails hydration because buttons are nested** ✔ (console: *"In HTML, `<button>` cannot be a descendant of `<button>` … Hydration failed"*; the Next.js dev overlay shows "3 Issues").
  - Location: `profiles/ProfilesClient.tsx:136`. The profile card is a `<button>` that contains the edit button (`:216`) and the delete button (`:233`).
  - React regenerates the tree on the client, and focus and screen-reader behaviour inside the card is undefined.
  - Fix: make the card a non-button container with a separate "switch" button, or use the overlay-link pattern.
- **[P1] The calendar's "This Cycle" fertile range is wrong** ✔
  - Location: `calendar/CalendarClient.tsx:633-634` takes the first and last fertile day in the visible month. In October it joins two fertile windows into "Oct 2 – Oct 30", while the dashboard says "Sep 26 – Oct 2".
  - Screenshot: `page-calendar-*-desktop.png`.
  - Fix: take the contiguous run that contains or follows today.

### P1: accessibility (see `a11y-perf-integrity.md`)

- **[P1] Many links and buttons have no focus-visible ring and there's no global fallback.** About 40 locations, starting with the shell nav (`layout.tsx:421,446,482,514,533,554,588`).
- **[P1] The Settings email and phone inputs are labelled only by their placeholder** (`SettingsClient.tsx:684-691`, `:732-739`).
- **[P1] Hard-coded English in aria-labels, errors and chrome bypasses i18n.** Examples: the auth brand panel, the calendar aria-labels, error and 404 pages, "Toggle theme", "Close dialog". The full list is in the report.

### P1: admin (see `admin.md`)

- A flash of the light theme before dark (same cause as web).
- The email preview is a light-only island in dark mode.
- Modals and the drawer have no focus trap, scroll lock or focus return.
- In the SMS modal, ESC on the date picker closes the whole modal, and the picker is clipped.
- The category manager doesn't respond to ESC.
- `ring-offset-2` halo (47 uses).
- Status colours use raw Tailwind steps and fail AA.

### P2: visual and layout observations from the screenshots (orchestrator)

- **Profile-completion banner on every page.** It's a centred, glowing card at the top of every signed-in page (about 70px tall on phones), while every page beneath it is left-aligned. The same nudge appears three times: the banner, the sidebar "Profile" pill, and the header ring chip on phones. → One entry point; align it to the page's left edge or fold it into the header ring.
- **Check-in is prompted in three ways on the dashboard:** the "Check in" pill, the "How are you feeling today?" nudge card, and the auto-opened modal. The nudge card also repeats on `/calendar` (`page-calendar-*`).
- **The sidebar "Symptoms" nudge outline still reads as a second active nav item** next to the filled active item. Review #12 changed the fill to an outline, but the outline is the same shape and colour as the active state.
- **Dashboard:**
  - The hero card's right half is empty on desktop.
  - The stat row mixes surfaces: Next Period is tinted, the others are white.
  - Quick Actions pairs a filled button with an outlined pill that has a chevron.
  - In Cycle Overview, the Follicular (pink) and Ovulation (gold) labels are coloured text on white.
- **Half-width primary cards next to full-width siblings:**
  - Profiles: the profile card vs "Add Profile".
  - Subscription: the plan card vs the comparison table.
  - Feedback: the form card vs an unstyled "No feedback yet" line floating top-right.
- **The calendar grid uses five day treatments:** solid, tinted, dashed pink box, bordered box and plain. In dark mode the fertile tints turn a muddy olive with white text (`page-calendar-desktop` pair).
- **Landing page:**
  - Everything below the hero renders only when it scrolls into view (`whileInView`). It's blank in non-scrolling captures and to anything that doesn't scroll.
  - Sections are sparse, with large dead gaps. "Cycle Overview" is just four coloured dots, and the trust pills are orphaned (`landing-*`).
- **Insights:** four tall empty-state cards repeat the same sentence, and the chart axis text is about 9px.
- **Onboarding header on phones:** the "1/5" step counter is clipped, the phone number crowds the language toggle, and "Cycle Circle" wraps (`fresh-onboarding-1-*-phone.png`).
- **Tiny text:** `text-[10px]`/`[11px]` is used in 48 places, including the dashboard cards, the chart axes and the bottom-nav labels.

The remaining P2/P3 findings are in the five slice reports. They cover the spacing scale, touch targets, tabular-nums, emoji-as-icon, the dead `DatePicker` and `LatePeriodPrompt`, reduced motion, blur cost, the UTC "today" in two modals, and the CelebrationModal auto-dismiss.

## Coverage gaps (not rendered; covered by code audit only)

- **Paywall / BDApps dialog.** Phone-auth users are automatically on the PRO tier (`getSubscriptionTier`), so no phone seed user, and no new phone user, ever sees "Upgrade to Pro". Rendering it needs an EMAIL-trial user (a Mailpit magic link).
- **`DatePicker`.** Not imported anywhere; it's dead code.
- **CelebrationModal.** Opening it requires saving a log, which would mutate the seed data. Not opened.
- **Calendar day detail.** It's an inline card rather than a sheet (`modals.md`), and the harness selector didn't match it.
- **Quick-symptom on desktop.** The `pop-quick-symptom-*-desktop` capture shows the auto-opened check-in sheet instead, because the auto-open fired first.
- **Period-log and quick-symptom triggers on phones.** The trigger clicks didn't register at the phone viewports. This may be related to the overflow or the fixed nav. Recheck after group B.
- **Admin.** Audited from code only, with no screenshots.

## What's working

- The brand token layer is coherent. The on-* pairs and the AA fallback rule from contracts.md are followed nearly everywhere, and the detector found no raw hex outside one internal page.
- `OnboardingTour` is a good reference implementation: it traps and restores focus.
- The base `Modal` already gets ESC, focus-on-open and labelling right. It's the seed for group A.
- Light-mode desktop pages read cleanly when looked at one at a time, and the problems are mostly between pages.
- The bilingual setup (i18n.ts plus a BN font) is solid. The gaps are hard-coded strings, not architecture.
