# The UI language lives in a cookie so the server renders it

The `vesta_lang` cookie (`en` | `bn`) is the source of truth for the UI language. The root layout reads it and passes it to `Providers`, which gives each server render its own i18n clone (the i18n singleton is shared across requests) and switches the client singleton and store to the same language before the first render, so hydration matches. Components read the language through `useLanguage()` (the i18n instance in context), never from the persisted store, because the store is a server-wide singleton during SSR. `setLanguage` writes the cookie; a one-time head script copies a localStorage-only Bengali choice into the cookie and reloads once. We chose this over keeping the language client-only because that rendered English on the server and switched after the layout hydrated, so every Bengali page hit a hydration mismatch, an English flash and a full client re-render. Reading the cookie makes every page dynamic (no static prerender); the user's `language` column in the DB is not used for this, since logged-out pages need it too. Decided 2026-10-18.
