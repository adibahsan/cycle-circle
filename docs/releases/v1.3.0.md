# Vesta v1.3.0

Production release building on **v1.0.0** — client review feedback, onboarding overhaul, pregnancy tracking, and admin improvements.

**Deployed:** Vercel (web + admin) + Supabase migration `20260616210000_v1_3_consolidated`

---

## Highlights

### Web app — user experience

- **Restructured onboarding flows** — new onboarding pages, welcome/get-started paths, and guided first-run experience
- **Onboarding product tour** — dismissible tour tracked via `onboardingTourCompletedAt`; replays from settings
- **Pregnancy mode tracker** — goal-oriented cycle tracking for pregnancy planning
- **Goal dashboard** — updated dashboard with goal-centric views and cycle intelligence
- **Profile & settings UI** — profile completion modal wiring, settings improvements, coloring/tint refinements across the app
- **Insights** — new insights surface for cycle patterns and user-facing analytics
- **Calendar & components** — calendar grid fixes, dropdown component fixes, Bengali/English styling and language fixes
- **Client review integration** — SRS and UI updates from v1.3 client feedback cycle

### Web app — backend & notifications

- **Profile completion reminders** — daily cron sends `PROFILE_COMPLETION_REMINDER` emails (14-day window, opt-out via settings)
- **Per-app auth cookies** — `AUTH_COOKIE_NAME` support; web uses `vesta_token` (default)
- **Expanded i18n** — major Bengali/English string additions (~789 lines in shared i18n)
- **User service** — onboarding tour completion, profile reminder opt-out, expanded user APIs
- **Insights service** — new shared service for cycle insights data

### Admin app

- **Analytics charts** — updated Recharts dashboards; fixed graph clip and dashboard mismatch issues
- **Content CMS** — category fixes, save button reliability
- **Pagination & exports** — pagination fixes across lists; CSV/XLSX extension and date format fixes; export alert dialog deduplication
- **Login UX** — password visibility (eye icon) on admin login
- **Auth cookie isolation** — `AUTH_COOKIE_NAME=vesta_admin_token` on production (separate from web sessions)

### Database

Migration `20260616210000_v1_3_consolidated` (additive, safe for existing users):

```sql
ALTER TYPE "EmailType" ADD VALUE 'PROFILE_COMPLETION_REMINDER';
ALTER TABLE "User" ADD COLUMN "onboardingTourCompletedAt" TIMESTAMP(3);
ALTER TABLE "User" ADD COLUMN "profileReminderOptOut" BOOLEAN NOT NULL DEFAULT false;
```

### DevOps & docs

- `apps/web/env.prod.example` — production env template
- `docs/SECURITY-ROTATION.md` — credential rotation checklist after secret purge
- Docker Compose / PostgreSQL version alignment in local setup docs

## Upgrade notes

1. **Apply DB migration before deploying apps:**
   ```bash
   cd packages/shared
   DIRECT_URL="..." pnpm db:migrate:deploy
   ```
2. **Vercel env (admin):** set `AUTH_COOKIE_NAME=vesta_admin_token`
3. **Vercel env (web):** `AUTH_COOKIE_NAME=vesta_token` optional (code default); recommended for explicit config
4. **No JWT rotation required** — existing sessions remain valid
