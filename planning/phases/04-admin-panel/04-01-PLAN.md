    1. Create `packages/shared/src/constants/roles.ts`:
       - Define `AdminRole` enum: `user`, `contentAdmin`, `superAdmin`
       - Define `ROLE_PERMISSIONS` map specifying which roles can access which admin sections:
         - `superAdmin`: all admin features (users, analytics, content, notifications, export, settings)
         - `contentAdmin`: content management only (articles, categories)
       - Export `isAdminRole(role: string): boolean` helper

    2. Create `packages/shared/src/schemas/admin.ts`:
       - `dashboardMetricsSchema`: Zod schema for dashboard response (totalUsers, activeUsers, profilesCreated, trackingActivity, dailyNewUsers trend array, monthlyActiveUsers trend array)

       - `userListQuerySchema`: extends paginationQuerySchema with role filter

    3. Create `packages/shared/src/types/admin.ts`:
       - Infer TypeScript types from Zod schemas: `DashboardMetrics`, `PaginationQuery`, `UserListQuery`
       - Define `AdminUser` type (id, email, role, isActive, createdAt, _count.profiles)

    4. Create `packages/api/src/middleware/requireRole.ts`:
       - Express middleware factory: `requireRole(...roles: AdminRole[])` returns middleware
       - Reads `req.user.role` (set by existing verifyJWT middleware)
       - If user role not in allowed roles, returns 403 `{ error: 'Insufficient permissions' }`
       - If no user on request, returns 401
       - Import role constants from shared package

    5. Create `packages/web/src/components/features/admin/RoleGuard.tsx`:
       - `RequireRole` component accepting `roles: AdminRole[]`, `children`, optional `fallback`
       - Uses `useAuth()` hook to get current user
       - If user role not in allowed roles, renders fallback or redirects to `/` via `<Navigate>`
       - Export for use in router configuration

    **Estimated effort: 4-6 developer-hours**

    1. Create `packages/api/src/services/admin-dashboard.service.ts`:
       - `getDashboardMetrics()` function:
         - Total users: `prisma.user.count()`
         - Active users (logged in within last 30 days): `prisma.user.count({ where: { lastLoginAt: { gte: thirtyDaysAgo } } })`
         - Total profiles: `prisma.profile.count()`
         - Tracking activity (users who logged cycle data in last 30 days): count distinct profileIds in CycleLog where date >= 30 days ago
       - `getDailyNewUsers(days: number)` function:
         - Uses Prisma `$queryRaw` with PostgreSQL `date_trunc('day', "createdAt")` to bucket user signups by day
         - Returns array of `{ date: string, count: number }` for last N days (default 30)
       - `getMonthlyActiveUsers(months: number)` function:
         - Uses Prisma `$queryRaw` with `date_trunc('month', "lastLoginAt")` for MAU trend
         - Returns array of `{ month: string, count: number }` for last N months (default 6)
       - `getProfileCreationTrend(days: number)` function:
         - Buckets profile creation by day, returns array
       - Cache results in Redis with 5-minute TTL (key: `admin:dashboard:metrics`)

    2. Create `packages/api/src/routes/admin/dashboard.routes.ts`:
       - `GET /api/admin/dashboard` -- requires superAdmin or contentAdmin
       - Middleware chain: verifyJWT -> requireRole('superAdmin', 'contentAdmin') -> handler
       - Handler calls service functions, returns DashboardMetrics shape validated against shared Zod schema
       - Query params: `days` (for trend period, default 30), validated with Zod

    3. Register admin routes in the main router (prefix `/api/admin`).
