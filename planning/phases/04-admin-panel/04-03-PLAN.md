  <action>
    **Estimated effort: 8-10 developer-hours**

    1. Create `packages/api/src/services/admin-analytics.service.ts`:

       **Privacy utility (CRITICAL -- used by all functions):**
       - `applyPrivacyThreshold<T>(groups: T[], minCount: number = 10): T[]` -- filters out groups with count below threshold to prevent individual identification

       **Health analytics (ADMN-05):**
       - `getHealthAnalytics()`:
         - Average cycle length: `prisma.cycleLog.aggregate({ _avg: { cycleLength: true }, _count: { id: true } })`
         - Irregular cycle percentage: Raw SQL query counting cycles where length < 21 or > 35 days, divided by total, multiplied by 100
         - Common symptoms: `prisma.symptomLog.groupBy({ by: ['symptomType'], _count: { id: true }, orderBy: { _count: { id: 'desc' } }, take: 10 })` -- apply privacy threshold
         - Symptom distribution by category (physical, mood, discharge, lifestyle): groupBy with category bucketing
         - Cycle length distribution: bucket into ranges (21-25, 26-30, 31-35, 36+) with counts

       **Profile monitoring / cycle insights (ADMN-04):**
       - `getCycleInsights()`:
         - Active tracking profiles: count of profiles with CycleLog entries in last 90 days
         - Average cycles per profile: aggregate cycle count divided by profile count
         - Phase distribution: how many profiles are currently in follicular/ovulatory/luteal/menstrual (calculated from last period date + average cycle length)
         - Tracking adoption: percentage of profiles with at least 1 cycle logged vs total profiles

       **Prediction accuracy (ADMN-06):**
       - `getPredictionAccuracy()`:
         - For each prediction tier (1, 2, 3), compare `Prediction.predictedDate` with `CycleLog.startDate` for the matching cycle
         - Calculate: mean absolute error (days off), accuracy within 1 day (%), accuracy within 3 days (%), accuracy within 7 days (%)
         - Return per-tier breakdown: `{ tier: number, totalPredictions: number, meanError: number, within1Day: number, within3Days: number, within7Days: number }`
         - Monthly accuracy trend: same metrics bucketed by month for trend chart
         - Use `$queryRaw` for the date comparison query (Prisma cannot express date_diff elegantly)

       **Cache all results in Redis with 5-minute TTL** (key pattern: `admin:analytics:{endpoint}`)

    2. Create `packages/api/src/routes/admin/analytics.routes.ts`:
       - `GET /api/admin/analytics/health` -- health analytics, requireRole('superAdmin')
       - `GET /api/admin/analytics/cycles` -- cycle insights/profile monitoring, requireRole('superAdmin')
       - `GET /api/admin/analytics/predictions` -- prediction accuracy, requireRole('superAdmin')
       - All endpoints: verifyJWT -> requireRole('superAdmin') -> handler
       - Query params: `period` (30d, 90d, 1y) for time-scoped analytics, validated with Zod

    3. Register analytics routes in admin router.
