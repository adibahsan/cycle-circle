    **Estimated effort: 10-12 developer-hours**

    **1. Notification management service + routes (ADMN-08):**

    Create `packages/api/src/services/admin-notifications.service.ts`:
    - `getNotificationConfig()`: Return current state of each notification type (periodPrediction, loggingReminder, fertileWindow) with enabled/disabled boolean and any configuration (send time, channel preferences). Read from a NotificationConfig table or JSON column on a settings table.
    - `updateNotificationConfig(type: string, config: Partial<NotifConfig>)`: Toggle notification types on/off, update send times. Validate notification type enum.
    - `sendBroadcast(data: BroadcastInput)`: Accept title, body, channel (email/sms/both), target (all users, active users, specific role). Queue via BullMQ with unique job ID (prevent duplicate sends). Store broadcast log: id, title, body, channel, targetCount, sentAt, sentBy.
    - `getBroadcastHistory()`: Paginated list of past broadcasts with status, recipient count, sent date, sender email.
    - Implement cooldown check: reject broadcast if another was sent within last 60 minutes (return error with time remaining).

    Create `packages/api/src/routes/admin/notifications.routes.ts`:
    - `GET /api/admin/notifications/config` -- current notification config, requireRole('superAdmin')
    - `PATCH /api/admin/notifications/config/:type` -- update config for a type, requireRole('superAdmin')
    - `POST /api/admin/notifications/broadcast` -- send broadcast, requireRole('superAdmin'), validate body
    - `GET /api/admin/notifications/broadcasts` -- broadcast history, requireRole('superAdmin')

    **2. Reports service + routes (ADMN-11, ADMN-12, ADMN-13, ADMN-14):**

    Create `packages/api/src/services/admin-reports.service.ts`:
    - `getFeatureUsageReport()` (ADMN-11):
      - Count active users per feature: CycleLog (period tracking), SymptomLog (symptom logging), Prediction (predictions used), calendar views (if tracked), partner shares, content views
      - Calculate: usage percentage = (profiles using feature / total active profiles) * 100
      - Return array of `{ feature: string, activeProfiles: number, totalProfiles: number, usagePct: number }`

    - `getAlertEngagementReport()` (ADMN-12):
      - Aggregate from NotificationLog table: total delivered, total opened (if tracked), total acted on (clicked/logged data within 1 hour of notification)
      - Funnel metrics: deliveryRate, openRate, actionRate
      - Breakdown by notification type (periodPrediction, loggingReminder, fertileWindow)
      - Return: `{ type: string, delivered: number, opened: number, actedOn: number, deliveryRate: number, openRate: number, actionRate: number }[]`

    - `getMultiProfileAnalytics()` (ADMN-13):
      - Total accounts (users) vs total profiles
      - Distribution of profiles per account: `prisma.user.findMany({ select: { _count: { select: { profiles: true } } } })` -> bucket into 1, 2, 3, 4, 5+ profiles
      - Relation type breakdown: `prisma.profile.groupBy({ by: ['relationType'], _count: { id: true } })`
      - Return: `{ totalAccounts, totalProfiles, avgProfilesPerAccount, profileDistribution: { count: number, accounts: number }[], relationTypeBreakdown: { type: string, count: number }[] }`

    - `getDataCompletenessReport()` (ADMN-14):
      - Classify each profile into completeness tiers:
        - Complete: has cycles logged + symptoms logged + predictions generated
        - Partial: has cycles logged but missing symptoms or predictions
        - Inactive: no cycle data logged
      - Use Prisma query with conditional counts: count profiles with CycleLog entries, with SymptomLog entries, with Predictions
      - Return: `{ complete: number, partial: number, inactive: number, total: number, completePct: number, partialPct: number, inactivePct: number }`

    Create `packages/api/src/routes/admin/reports.routes.ts`:
    - `GET /api/admin/reports/feature-usage` -- requireRole('superAdmin')
    - `GET /api/admin/reports/alert-engagement` -- requireRole('superAdmin')
    - `GET /api/admin/reports/multi-profile` -- requireRole('superAdmin')
    - `GET /api/admin/reports/data-completeness` -- requireRole('superAdmin')
    - All endpoints cached in Redis with 5-minute TTL

    **3. Export service + routes (ADMN-10):**

    Create `packages/api/src/services/admin-export.service.ts`:
    - `getExportData(type: ExportType, params: ExportParams)`: Fetch data for export based on type:
      - `users`: User list (id, email, role, status, profileCount, joinedDate, lastLogin)
      - `health-analytics`: Aggregated health metrics (same as analytics endpoint, flattened for tabular format)
      - `prediction-accuracy`: Per-tier accuracy data flattened
      - `feature-usage`: Feature usage report data
      - `alert-engagement`: Alert engagement report data
      - `multi-profile`: Multi-profile analytics data
      - `data-completeness`: Data completeness report data
    - Return typed arrays ready for CSV/Excel serialization
    - Maximum 100K rows per export. Return error if exceeded.

    Create `packages/api/src/routes/admin/export.routes.ts`:
    - `GET /api/admin/export/:type` -- requireRole('superAdmin')
    - Query params: format (csv/json), dateRange (start, end), validated with Zod
    - Returns JSON data (client-side rendering to CSV/Excel via ExcelJS)
    - Alternative: server-side CSV generation streaming as `text/csv` Content-Type for large exports

    Register all routes in admin router.
