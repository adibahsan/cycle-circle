    - symptomService.logSymptom(profileId, { date, category, symptoms, notes? }) creates or upserts a SymptomLog
    - When a log already exists for the same profileId + date + category, it updates (upsert) rather than creating a duplicate (SYMP-07)
    - symptomService.getSymptomsByDate(profileId, date) returns all SymptomLog entries for that date across categories
    - symptomService.getSymptomsByDateRange(profileId, startDate, endDate) returns logs for calendar display
    - symptomService.updatePreferences(profileId, { visibleCategories }) updates profile.symptomPreferences JSON
    - symptomService.getPreferences(profileId) returns SymptomPreferences (default: all 4 categories visible)
    - After logging symptoms, enqueue prediction recalc (SYMP-08)
    - POST /profiles/:pid/symptoms validates body with logSymptomSchema
    - GET /profiles/:pid/symptoms?date=2026-03-15 returns symptoms for that date
    - GET /profiles/:pid/symptoms?start=2026-03-01&end=2026-03-31 returns symptoms for date range
    - PUT /profiles/:pid/symptoms/preferences validates body with updateSymptomPrefsSchema
    - GET /profiles/:pid/symptoms/preferences returns current preferences
  </behavior>
  <action>
    **Symptom Service (packages/api/src/services/symptom.service.ts):**

    1. `logSymptom(profileId, data)`: Use Prisma upsert with composite unique key [profileId, date, category]. This handles both create (new log) and update (SYMP-07 edit same-day log) in a single operation. After upsert, call enqueuePredictionRecalc(profileId) to satisfy SYMP-08. Notes field will be encrypted via prisma-field-encryption extension.

    2. `getSymptomsByDate(profileId, date)`: Query SymptomLog WHERE profileId AND date. Return all categories for that date.

    3. `getSymptomsByDateRange(profileId, startDate, endDate)`: Query WHERE profileId AND date >= startDate AND date <= endDate. Order by date DESC. Used by calendar (Plan 06) to show symptom indicators.

    4. `updatePreferences(profileId, prefs)`: Update Profile.symptomPreferences JSON field. Default value if null: { visibleCategories: ['physical','mood','discharge','lifestyle'] }.

    5. `getPreferences(profileId)`: Read Profile.symptomPreferences. Return default if null.

    **Symptom Routes (packages/api/src/routes/symptom.routes.ts):**

    Mount on `/profiles/:profileId/symptoms`:
    - POST `/` -- logSymptom (logSymptomSchema validation)
    - GET `/` -- getSymptoms (query params: date OR start+end)
    - PUT `/preferences` -- updatePreferences (updateSymptomPrefsSchema validation)
    - GET `/preferences` -- getPreferences

    All routes: verifyJWT -> checkProfileOwnership -> validateBody(schema) -> controller. Follow the exact pattern from cycle.routes.ts and profile.routes.ts.
