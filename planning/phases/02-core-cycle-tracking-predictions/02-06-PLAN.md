  <action>
    Create `useCalendarData(profileId, displayMonth: Date)` hook that:

    1. **Fetches data for the display month** (plus padding for start/end of month grid):
       - `useCycles(profileId)` -- all logged cycles
       - `useMultiPredictions(profileId, 3)` -- next 3 predicted cycles
       - `useSymptomsByDateRange(profileId, monthStart, monthEnd)` -- symptom indicators

    2. **Generates the month grid** using date-fns:
       - `startOfMonth(displayMonth)` and `endOfMonth(displayMonth)`
       - Pad to full weeks: `startOfWeek(startOfMonth)` to `endOfWeek(endOfMonth)`
       - `eachDayOfInterval(padded range)` -> Date[]

    3. **Computes DayStatus for each day:**

       For each day in the grid:
       a. **Check logged data:** Is this day within any CycleLog's startDate-endDate range? If yes: isLogged=true, isPeriod=true, flowIntensity from the log.
       b. **Check predicted data:** If not logged, is this day within a predicted period range (prediction.nextPeriodStart to nextPeriodEnd)? If yes: isPredicted=true, isPeriod=true.
       c. **Check fertile window:** Is this day within a fertile window (logged or predicted)? If yes: isFertile=true. Is it the ovulation day? isOvulation=true.
       d. **Check symptoms:** Does a SymptomLog exist for this date? If yes: hasSymptoms=true.
       e. **Today check:** isSameDay(day, today).

       Key distinction (per research Pitfall 4): Logged days get `isLogged=true`, predicted days get `isPredicted=true`. Calendar visuals differ.

    4. **Returns:** `{ days: DayStatus[], isLoading, error, displayMonth }`

    **Performance:** Memoize the DayStatus computation with useMemo, keyed on cycles data, predictions data, symptoms data, and displayMonth. This prevents recalculation on every render.
