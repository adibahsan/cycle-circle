<objective>
Build the complete partner sharing system: share code generation and redemption, partner access middleware enforcing read-only permissions with field-level filtering (symptoms excluded), partner-scoped API endpoints for calendar and phase view, daily partner insight notifications via BullMQ, email templates for partner invite and daily insights, and the full frontend for both the profile owner (share management) and the partner (read-only cycle view).

Purpose: Partner sharing is a key engagement feature that extends Vesta's value beyond the primary user. It supports the Bangladeshi cultural context where family members (husbands, mothers) are involved in reproductive health awareness, while maintaining strict data boundaries -- the partner sees calendar and phase data but never symptoms or editable data.

Output: Share code generation/redemption API, partner access middleware, read-only partner endpoints, daily insight cron job, partner invite and insight email templates, share management page, partner read-only view with calendar and phase display.
</objective>

  <action>
    **Estimated effort: 8 developer-hours**

    1. Create packages/api/src/services/partner.service.ts:
       - createPartnerShare(profileId: string, userId: string): string
         - Verify user owns the profile (prisma.profile.findFirst where id + userId)
         - Revoke existing active shares: updateMany where profileId + isActive true -> set isActive false, revokedAt now
         - Load profile to check goalType for TTC permissions
         - Generate code with generateShareCode() from utils/shareCode.ts
         - Create PartnerAccess record with default permissions: { calendar: true, phaseInsight: true, fertileWindow: profile.goalType === 'TTC', symptoms: false, notes: false }
         - Set expiresAt to 7 days from now (code expiry, not access expiry)
         - partnerUserId set to empty string (populated on redemption)
         - Return the generated code

       - redeemShareCode(code: string, partnerUserId: string): PartnerRedeemResult
         - Find PartnerAccess by shareCode where isActive true
         - Validate: not expired (expiresAt > now or null), partnerUserId is still empty (not already redeemed)
         - Validate: partnerUserId !== profile owner userId (cannot share with yourself)
         - Update record: set partnerUserId, clear expiresAt (access is now permanent until revoked)
         - Return profile name and profileId for the partner's view

       - getCalendarView(profileId: string, permissions: PartnerPermissions): PartnerCalendarView
         - Load last 6 cycles: startDate, endDate, flowIntensity (NEVER symptoms -- PRTN-05)
         - Load latest prediction: nextPeriod, tier, confidence. Include ovulation/fertileStart/fertileEnd ONLY if permissions.fertileWindow is true (PRTN-04).
         - Load profile: name, cycleLength, goalType
         - Calculate currentPhase from prediction
         - Return structured PartnerCalendarView

       - getPhaseInsight(profileId: string): PartnerPhaseInsight
         - Load latest prediction and calculate current phase
         - Return: phase name, day in phase, days until next period, brief insight text (localized)

       - revokeAccess(profileId: string, userId: string): void
         - Update all PartnerAccess where profileId + isActive true: set isActive false, revokedAt now
         - No Redis cache to clear (partner endpoints use short cache headers)

       - listActiveShares(profileId: string, userId: string): PartnerAccess[]
         - Return active partner shares for the profile (for the management UI)

    2. Create packages/api/src/middleware/partnerAccess.ts:
       - checkPartnerAccess(req, res, next):
         - Extract profileId from req.params, userId from req.user (JWT)
         - Query PartnerAccess where profileId + partnerUserId=userId + isActive=true + (expiresAt null OR > now)
         - If not found: return 403 { error: 'Partner access denied or revoked' }
         - If found: attach permissions to req.partnerPermissions (as PartnerPermissions type)
         - Call next()

    3. Create packages/api/src/routes/partner.routes.ts:
       - POST /profiles/:profileId/partner/share -- verifyJWT + checkProfileOwnership. Creates share code. Returns { code: string, expiresAt: string }.
       - POST /partner/redeem -- verifyJWT. Body: { code: string }. Redeems share code for authenticated user. Returns { profileId, profileName }.
       - GET /partner/:profileId/calendar -- verifyJWT + checkPartnerAccess (NOT checkProfileOwnership). Returns filtered calendar view.
       - GET /partner/:profileId/phase -- verifyJWT + checkPartnerAccess. Returns current phase insight.
       - DELETE /profiles/:profileId/partner/revoke -- verifyJWT + checkProfileOwnership. Revokes all active partner access.
       - GET /profiles/:profileId/partner/shares -- verifyJWT + checkProfileOwnership. Lists active shares.
       - CRITICAL: All /partner/:profileId/* endpoints (partner's view) use checkPartnerAccess, NOT checkProfileOwnership. The partner is NOT the profile owner.
       - All partner view endpoints are GET-only (PRTN-05).
       - Export partnerRouter

       - Test redeemShareCode with expired code returns error
       - Test redeemShareCode with already-redeemed code returns error

       - Test getCalendarView with fertileWindow=true includes fertile window data
